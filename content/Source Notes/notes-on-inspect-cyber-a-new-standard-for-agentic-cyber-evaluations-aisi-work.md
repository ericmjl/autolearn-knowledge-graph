## What it says

UK AISI releases Inspect Cyber, an open-source Python package that standardises agentic cyber evaluations into two configuration files (one for the evaluation, one for its infrastructure), so developers build environments instead of setup code. It inherits the Inspect platform's support for diverse models, custom agents, scoring mechanisms, sandbox environments, and human-oversight or baselining policies, and it pushes practice toward verifying solvability, variant testing, and reproducible project structure.

## Claims drawn from this source

- **Agentic cyber evals need standardized setup.** Every new evaluation or benchmark requires the same repetitive setup: creating sandboxed infrastructure, connecting agents to models, and developing run scripts.
- **Standardization trades setup code for environment focus.** Lack of standardization makes development time balloon and pushes creators away from the core component of the evaluation, the environment in which the agent is placed.
- **Inspect Cyber is built on two config files.** It provides a clear, consistent process for creating agentic cyber evaluations using just two configuration files, one for the evaluation and another for its required infrastructure.
- **Inspect Cyber produces evaluation variants.** Researchers can easily produce multiple variants of an evaluation, such as with different agent prompts or affordances.
- **Inspect Cyber promotes verifying solvability.** It promotes AI evaluation best practices, such as verifying solvability.
- **Inspect Cyber inherits Inspect's machinery.** Because it is built on Inspect, it supports running evaluations across diverse models using custom agents, scoring mechanisms, sandbox environments, and policies for human oversight or baselining.
- **Inspect Cyber handles a spectrum of scenarios.** AISI used it internally across Capture the Flag challenges to sophisticated cyber ranges simulating Active Directory services, enterprise networks, and critical national infrastructure.
