## What it says

AWS describes a nine-stage, multi-level evaluation framework for production agents, treating quality as the operating system of the agent rather than a final QA step. At each level (tool, agent, multi-agent) a golden set is built from production-derived, failure-derived, and synthetic sources and checked by a sentinel set on every staging deploy and a full Quality Gate before launch, with canary scoring, drift detection on 10 percent of live traffic, and a feedback loop that promotes low-scoring sessions back into the golden set as permanent regression guards.

## Claims drawn from this source

- **Agents fail softly: fluent, confident, wrong answers slip past monitoring.** The post opens by noting that traditional software fails loudly but agents return answers that look confident, read fluently, and are wrong, with latency low and error rates flat while quality erodes. Before launch, the Customer Insights Agent reported $410.08 of revenue as '$410.08 Million' and presented its own calculations as sourced facts, while monitoring stayed green.
- **Six production-derived failure types define the accuracy taxonomy.** Metric swap (correct customer and period, wrong metric), wrong period (YoY figure labeled as MoM), wrong entity (conflated account names or subsidiaries), pure hallucination (ungrounded figures with no traceable source), wrong symbols (correct metric, wrong unit), and unauthorized calculation (derived figures not present in source data). Each maps to a customized evaluator since none is covered by native templates.
- **Hands-on tool testing happens before the agent is involved.** Before an agent is tested, each tool is tested on its own: a held-out set of inputs from the golden set where the correct answer is already known is scored against what the tool actually returns, then the validated answers are frozen into a replay dataset the agent sees during the gate. This isolates whether the tool works (entity resolution, retrieval, SQL generation) from the agent's reasoning.
- **The golden set is a living document built from three sources.** Production-derived cases from real queries including low-scoring live sessions promoted in drift detection, failure-derived cases from every regression caught in staging or production, and synthetic edge cases deliberately constructed to cover scenarios that cannot be waited for in the wild, such as ticker-symbol disambiguation and the four question types (comprehensive, reporting, reasoning, ambiguous).
- **The sentinel set is small, fast, and reviewed monthly.** The sentinel covers 15 cases per level (tool, agent, multi-agent) and runs in minutes on every staging deploy; it is reviewed monthly and a regression that slips through to production is immediately promoted into a permanent case. An example: a data normalization update left a disambiguation tool returning unresolved entities for a subset of account name formats, the tool-level sentinel block the deployment automatically.
- **The Quality Gate runs a 200-question held-out end-to-end pass with three automatic stop conditions.** The candidate agent answers 200 held-out questions scored by an LLM-as-judge rubric across all evaluator dimensions. The gate shuts if the aggregate score regresses against the candidate's own prior run, fails to beat the current production baseline, or more than a defined percentage of questions falls below the per-question threshold.
- **Canary cadence: 30-minute windows, three-window paging, daily full-golden-set confirmation.** 15-minute cycles generated too many false alarms and 60-minute cycles let two hours pass before a real degradation registered, so 30-minute windows catch a trend within 90 minutes with three consecutive window failures before oncall is paged. Each window scores a round-robin selection across the golden set for full coverage in 24 hours; once per day the full golden set runs at gate thresholds as the authoritative daily scorecard.
- **Drift detection promotes low-scoring live sessions back into the golden set.** 10 percent of live traffic is sampled continuously through the evaluators; the Quality-State Calculator surfaced 98 percent at 1:30am, 81 percent at 2:00am, and 80 percent at 2:30am as sellers queried with ticker symbols and shorthand names. The fix expanded the golden set with the low-scoring sessions and update the disambiguation tool to normalize input formats; accuracy recovered within the next evaluation cycle.
