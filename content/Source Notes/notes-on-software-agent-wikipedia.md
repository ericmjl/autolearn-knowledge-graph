## What it says

The source defines a software agent as a program that acts for a user or another program with authority to decide appropriate action, distinguishing agents from ordinary programs by reaction, autonomy, goal-orientation, and persistence. It surveys agent types (buyer, user, monitoring, data-mining, networking, software-development, security) and the design issues for agent-based systems, including scheduling, prioritization, collaboration, state, environment probing, messaging, and agent hierarchies. It also notes organizational and cultural effects of agents, such as higher work contentment alongside trust, skills-erosion, privacy, and social-detachment risks. For building agents, it emphasizes shared semantics/metadata, interaction protocols, security verification of actions, and transparent bot behavior.

## Claims drawn from this source

- **Agents act on behalf of users with decision authority.** The term agent implies an agreement to act on one's behalf, including authority to decide which, if any, action is appropriate.
- **Autonomy distinguishes agents from plain programs.** Autonomous agents activate themselves, may wait and perceive context, run on starting conditions, and do not require user interaction. Franklin & Graesser distinguish agents from arbitrary programs by reaction to environment, autonomy, goal-orientation, and persistence.
- **Agents are defined by behavior, not methods/attributes.** Unlike objects, which are defined in terms of methods and attributes, an agent is defined in terms of its behavior.
- **Collaboration requires shared semantics and protocols.** Agents working together efficiently must share semantics of their data elements, e.g. by publishing metadata, and agent processing combines internal state/ontologies with interaction protocols.
- **Agent actions pass through security verification.** After deciding to act, an agent's action is verified by a security function and then given the authority of the user before delivery.
- **Security agents intercept and act on content.** DLP, EDR, and CASB agents examine user operations, endpoint activity, or cloud-application traffic and can allow, alert, or block.
- **Bots should be transparent and respectful.** Bots should identify themselves in the user-agent HTTP header, validate source IP, respect robots.txt, and avoid excessive aggression or ignore crawl-delay instructions.
- **Agents carry organizational and cultural risks.** They can raise work contentment and self-controlled work, but also trust affliction, skills erosion, privacy attrition, and social detachment.
